# Імітаційна модель обчислювальної системи зі спільною оперативною пам'яттю

Курсова робота з освітнього компонента «Моделювання систем. Курсова робота»
(КПІ ім. Ігоря Сікорського, ФІОТ, кафедра ІПІ). Завдання D4, формалізм — стохастична мережа Петрі.

Обчислювальна система обробляє завдання трьома послідовними процесорами зі спільною оперативною
пам'яттю. Завдання надходять через 5±2 хв і займають одну сторінку пам'яті; після трансляції
(5±1 хв) — дві сторінки, після редагування (2,5±0,5 хв на сторінку) — три; після обробки третім
процесором (1,5±0,4 хв на сторінку) пам'ять звільняється. Мета — визначити характеристики зайняття
пам'яті та дослідити їх зміну зі зростанням інтенсивності надходження завдань.

## Модель

- Пам'ять обмежена `M` сторінками; вільні сторінки — маркери позиції «Вільна ОП».
- Правило порогів вільних сторінок 3/2/1 (допуск / зростання після P1 / зростання після P2)
  виключає взаємоблокування: завдання допускається, лише якщо вільних сторінок не менше ніж три,
  інакше отримує відмову.
- Кількості допущених, відмовлених і оброблених завдань визначаються за маркіруванням
  позицій-лічильників.

Алгоритм імітації побудовано за алгоритмом класу `PetriSim` бібліотеки PetriObjLib програмного
забезпечення [PetriObjModelPaint](https://github.com/StetsenkoInna/PetriObjModelPaint) (модуль
petri-math, ліцензія MIT, І. В. Стеценко) зі спрощеннями під задачу: одноканальні часові переходи,
атомарний запуск миттєвих переходів, вирішення конфліктів за пріоритетом, генератор із заданим
зерном. Перед імітацією перевіряється правильність конструювання мережі, а під час імітації —
невід'ємність затримок.

## Структура

| Пакет | Вміст |
|---|---|
| `ua.kpi.cmdes.petri` | Ядро стохастичної мережі Петрі: позиції, переходи, дуги, алгоритм імітації |
| `ua.kpi.cmdes.stats` | Статистика, зважена за часом, критерії χ², Фішера, Стьюдента, Кохрена, метод найменших квадратів, дисперсійний аналіз |
| `ua.kpi.cmdes.model` | Мережа Петрі обчислювальної системи, збір вихідних характеристик, протокол подій |
| `ua.kpi.cmdes.experiment` | Верифікація та експериментальне дослідження |

## Запуск

Потрібні JDK 25 і Maven.

```sh
mvn test                      # автоматичні тести моделі
mvn compile exec:java         # пробний прогін з початковими значеннями
mvn compile exec:java -Dmain.class=ua.kpi.cmdes.experiment.Verification
```

Програми експериментального дослідження (клас передається через `-Dmain.class=...`):

| Клас | Призначення |
|---|---|
| `experiment.Verification` | Верифікація варіюванням кожної вхідної змінної та закону розподілу |
| `experiment.ProtocolDemo` | Фрагмент протоколу подій |
| `experiment.TransientAnalysis` | Тривалість перехідного періоду |
| `experiment.RunCountEstimation` | Кількість прогонів для заданої точності |
| `experiment.DistributionAnalysis` | Закон розподілу кількості зайнятих сторінок |
| `experiment.IntensityExperiment` | Вплив інтенсивності надходження та обсягу пам'яті; кількість прогонів у кожній точці уточнюється до точності 0,25 сторінки |
| `experiment.RegressionAnalysis` | Регресійний аналіз з перевірками Кохрена, Стьюдента, Фішера (за результатами `IntensityExperiment`) |
| `experiment.MemoryFactorAnova` | Дисперсійний аналіз впливу обсягу пам'яті |
| `experiment.ProposalsExperiment` | Пробні прогони для пропозицій і дисперсійний аналіз «базова / модифікована модель» |

Результати записуються в теку `results/` (інша тека — `-Dresults.dir=...`). У репозиторії вже
є результати, отримані для пояснювальної записки.

## Основні результати

- За початкових даних (`M = 30`) перший і другий процесори завантажені повністю; пам'ять зайнята
  в середньому на 18,06 ± 0,24 сторінки (60 %).
- До інтенсивності 0,19 завдання/хв зайнята пам'ять мала (3,6–6,5 сторінки) і не залежить від `M`;
  в околі 0,2 завдання/хв вона стрибкоподібно зростає, а далі наближається до `M − 2`.
- Пришвидшення першого та другого процесорів на 10 % зменшує зайняту пам'ять до 6,0 сторінки,
  а час перебування завдання — з 61,9 до 15,3 хв.
